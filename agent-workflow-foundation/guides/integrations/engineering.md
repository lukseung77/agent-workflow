# Engineering Integrations

Use `workflow/tooling.md` for the common install, inventory, update,
and retirement procedure. Official origins are keyed below in the registry.
These integrations fit Exploration discovery or Implementation/review activity.

| Registry ID | Setup and when to use | Verify and apply | Fallback / retirement |
|---|---|---|---|
| `ponytail` | Use implementation-minimalism guidance when implementing an accepted feature. Follow the origin's current native host installer if its plugin is wanted; `guides/tooling-operations.md` covers the existing adapter. | Verify native plugin discovery separately from the foundation policy pointer. Check a proposed simplification preserves required behavior, tests, accessibility, and security. | Ordinary source review supplies the discipline. Disable only the recorded plugin/configuration; retaining the shared policy is valid. |
| `graphify` | Install the official `graphifyy` package in a supported isolated environment for structural repository discovery. Use the existing environment adapter when selected. | Verify CLI identity/version, build or refresh the project's index, and check sampled nodes/edges against current source. Record index location and refresh point. | Use source search. Remove generated indexes only after confirming their ownership; source wins over stale graphs. |
| `floorplan` | Install its current host plugin when a builder needs an interactive plain-language app map. Choose it over an additional index if explanation is the main need. | Map one user journey, inspect the rendered map, and trace representative file/request links back to source. Record map generation time and source revision. | Use a small source-backed diagram. Retire generated maps and the selected plugin separately. |
| `ecc` | Select individual skills from the official collection using its supported host installation. Inspect sibling dependencies and hook/configuration effects. | Invoke only the selected capability on a bounded task and check its output against project requirements. Record each selected skill and revision rather than claiming the entire harness is active. | Existing foundation procedures remain available. Do not replace authority, task state, memory, or review gates with collection defaults. |
| `addy-agent-skills` | Select a specific review, debugging, testing, or interview skill using current host-supported installation. Avoid bulk-loading the collection. | Verify discovery and a representative task, noting any host-specific command/plugin differences. Inspect instructions that delegate or impose a separate workflow before using them. | Native tools and foundation review/question rules remain the fallback. Remove only selected skills and unneeded dependencies. |

Graphify and Floorplan can coexist when source indexing and human-facing
explanation are both needed; do not generate two maps routinely. ECC and Addy's
collection can supply different skills, but choose one primary procedure for a
given task. Existing tests and accepted architecture govern all simplifications.
